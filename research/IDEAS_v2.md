# 升级方案 v2：让 planner 学会诚实地给自己打分

日期：2026-10-26。承接 `IDEAS.md`（v1）和 `PREREG_direction1.md`。硬件：4 × NVIDIA RTX PRO 5000 Blackwell 72GB。

## 0. 为什么要升级 v1 的方向一

v1 的中稿估计偏低（约 10%），原因有三个。这次新查到的近邻让其中两个变得更严重：

1. **估计量本身已有近邻。**
   - [MFPG-PPO (2610.02505)](https://arxiv.org/abs/2610.02505)（2026-10-01）用便宜的低保真数据构造控制变量，保持策略梯度无偏，并且已经在 Franka 真机上做了实验；它的前作 [MFPG (2503.05696)](https://arxiv.org/abs/2503.05696) 更早。
   - "用便宜信号加少量真值做无偏梯度"这个数学结构，审稿人会直接指向它们。
2. **"共同随机数 / 配对 rollout"也已有人做过。** [Luck Is Not Skill (2609.24144)](https://arxiv.org/abs/2609.24144)（2026-09-21）研究了它对 LLM agent 组内比较 RL 的作用，结论是"比较更准，但不保证梯度方差更低，也不保证学得更快"。
3. **在线效应太小。** 论文里 RL 总共只比 SFT 多 5.9 个点，各组差异被压缩在这个区间里，统计功效不够。

升级思路：把贡献从"一个新估计量"挪到一个**新的结构性观点**上，并让主要主张落在统计功效高、不依赖小幅成功率差异的指标上。

> agentic 设定里，用来降低方差的控制变量可以由 **agent 自己产出**（它对自己是否成功的概率判断）。
> 用恰当评分规则（proper scoring rule）加上 prediction-powered 奖励，可以把激励设计成：
> agent 如实报告，并且主动把自己的判断变准；而这恰好就是在降低它自己学习信号的方差。

## 1. 主方案 A：Self-Grading Planner

暂定题目：*Grade Yourself Honestly: Incentive-Compatible Self-Verification for Label-Efficient Post-Training of Robot Planners*

### 1.1 借用的跨领域工具

| 领域 | 工具 | 在本文中的作用 |
|---|---|---|
| 统计 / 预报理论 | 恰当评分规则（Brier）及其 Murphy 分解（校准 + 分辨率） | agent 报告成功概率 p；Brier 奖励使如实报告成为最优，分辨率项量化"知道自己是否成功"的程度 |
| 统计推断 | Prediction-powered inference、控制变量、IPW | 少量随机真标签加 agent 的 p，构造无偏奖励 |
| 机制设计 / 信息经济学 | 策略防操纵（strategyproofness）、Bayesian persuasion（Kamenica & Gentzkow 2011） | 解释"agent 控制评判看到的证据"为什么会导致 hacking，并证明 PP 奖励使操纵在期望上毫无收益 |
| 主动学习 / 实验设计 | Neyman 最优分配 | 标签该要给谁：最优规则恰好是 agent 自报的不确定度 √(p(1−p)) |
| 机器人 | KnowNo、introspective planning（conformal "不确定时求助"） | 我们用 RL 学出校准的自评，并把它同时用于学习和求助 |

### 1.2 设定

- **harness**：无 oracle 版 RPent（`terminated` 及两条侧信道已屏蔽，见 `PREREG_direction1.md` W2）。
- **planner 输出**：结束时调用 `finish(status, confidence=p)`，p ∈ [0, 1]。
- **真结局 r**：final-state 成功，只在被抽中标注时揭示，标注概率 q_i 可以依赖 p_i。

### 1.3 方法（每个回合一个标量奖励，接入方式与 v1 相同，只改 `build_round.py`）

$$\tilde r = \lambda p + \frac{\xi}{q}(r-\lambda p),\qquad \tilde S = -p^2 + (2p-1)\,\tilde r,\qquad R = \tilde r + \beta\,\tilde S$$

其中 ξ ~ Bernoulli(q)。对二值 r，Brier 分数 −(p − r)² 关于 r 是仿射的，所以把 r̃ 代入就得到 Brier 分数的无偏估计 S̃。λ 用别的组的标签交叉拟合。标注规则取 q_i ∝ √(p_i(1−p_i))，截断到 [q_min, 1]，并满足预算约束。

### 1.4 要证明的性质（证明都只有几行，但组合起来是新的）

- **T1 策略防操纵（strategyproof）**：对任意策略，包括会操纵 p 或操纵证据（何时结束、拍哪个视角）的策略，都有 E[r̃ | τ] = r，所以 r̃ 下的最优策略集合与真奖励下完全相同。对比：
  - 只用代理奖励（reward = p）时，最优策略就是永远报 p = 1；
  - 代理是 VLM 判官时，agent 选择展示哪些证据，就是一个 Bayesian persuasion 问题。对理性判官，可操纵出的最大假阳率由凹化（concavification）给出（判官阈值为 1/2、先验成功率 s < 1/2 时约为 s/(1−s)）；对"天真"的 VLM 判官则没有上界。
- **T2 激励对齐**：记 b 为 agent 结束时的后验成功概率。期望奖励 E[R | b, p] = b − β[(p − b)² + b(1−b)]，因此：
  - (i) 对任意 β > 0，如实报告 p = b 是唯一最优；
  - (ii) 如实报告时价值为 φ(b) = (1−β)b + βb²。β ≤ 1 时 φ 关于 b 单调递增，agent 永远不会为了"更好预测"而牺牲成功率。这一点推广了 RLCR 的结论：RLCR 用全标签、单轮问答；我们用 PP 估计、多轮交互；
  - (iii) φ 是凸函数，所以 agent 有动力在结束前收集验证证据（比如换 wrist 视角确认）。信息的价值恰好等于 β × 后验方差的期望减少量，也就是 β × Brier 分辨率的提升。这给出一个可检验的行为预测："学会先看再交卷"。
- **T3 方差恒等式**：标签校正项的条件方差为 (1−q)/q · (r − λp)²。λ = 1、q 恒定时，它的期望就是 (1−q)/q × Brier(p)。
  - 所以 agent 每把自评变准一点，它自己学习信号中的标签噪声就线性下降：**agent 被奖励去降低自己梯度的方差**。
  - 这是本文最核心、也最"新"的一句话。MFPG 的控制变量来自外部的低保真仿真器，不会随训练变好；我们的控制变量会。
- **T4 最优求助规则**：在预算约束下最小化方差，得到 q_i ∝ √(E[(r − λp)² | τ_i]) · ‖g_i‖。p 校准时，前一个因子就是 √(p(1−p))：agent 越不确定越该要标签，而且只要做 IPW 加权就保持无偏。agent 可以通过 p 影响 q，但由 T1，这不改变期望奖励，所以不产生操纵激励。

### 1.5 与近邻的差异

| 工作 | 他们做了什么 | 我们多出来的部分 |
|---|---|---|
| [RLCR (2507.16806)](https://arxiv.org/abs/2507.16806) | 正确性 + Brier 奖励，证明能同时得到准确和校准的模型 | 他们需要全标签、单轮问答；我们是稀疏标签，自评同时充当控制变量，还有方差恒等式和多轮验证行为 |
| [MFPG-PPO (2610.02505)](https://arxiv.org/abs/2610.02505) | 低保真数据作控制变量，无偏 PG | 我们的控制变量由 agent 产出，并被激励去改进；还有策略相关误差下的防操纵性 |
| [RLAVR (2605.25864)](https://arxiv.org/abs/2605.25864) | 主动标注 + 伪标签 | 我们无偏、有最优分配的闭式解，求助规则来自 agent 自身 |
| [PGBC (2510.00915)](https://arxiv.org/abs/2510.00915) | 固定误差率的噪声校正 | 我们对任意策略相关误差都有效 |
| [KnowNo (CoRL 2023)](https://arxiv.org/abs/2307.01928)、introspective planning（NeurIPS 2024） | conformal 预测决定何时求助 | 我们用 RL 学出校准的自评，并同时用于学习信号和标注请求 |
| [FailBench (2609.03611)](https://arxiv.org/abs/2609.03611)、[VLMeg (2610.15401)](https://arxiv.org/abs/2610.15401) | 外部 VLM 判官 | 判官由 agent 自己担任，并用激励设计防止它自欺 |

### 1.6 实验（比 v1 精简，主要主张落在高功效指标上）

| arm | 内容 | 种子数 |
|---|---|---|
| R0 | 全标签 RLOO（论文算法，无 oracle harness） | 2 |
| L10 | 仅标签 10%（IPW + 基线） | 2 |
| S-self | reward = p（只用自报作奖励），预期学会永远宣称成功 | 1 |
| P10 | PP 用 p 作控制变量，不加 Brier 项（隔离 T3 的效果） | 1 |
| SG10 | 本文方法，均匀标注 10% | 1 |
| **SG10-ask** | 本文方法，按 √(p(1−p)) 标注 | 2 |

共 9 个 run（v1 是 15 个）。另外：E1 离线方差与梯度保真度实验；ALFWorld / WebShop 上用 Qwen3-4B 复现同一组 arm（便宜、功效高）；LIBERO-Plus 子集测迁移。

主要主张及其统计功效：

| 主张 | 指标 | 功效 |
|---|---|---|
| 只用自报会被钻空子；SG 不会 | S-self 的 p 均值和假阳率逐轮变化（预期接近 1） | 效应量极大 |
| SG 的自评是校准的，而全标签 RLOO 会让校准变差（RLCR 已在问答上观察到这一点） | 每轮 768 回合上的 ECE / Brier | 高 |
| 学会"先验证再交卷"（T2-iii） | 结束前验证类动作的频率 | 高 |
| 标签效率（T3、T4） | E1 中的梯度方差、梯度余弦随 Brier 的变化 | 高（离线，可反复重抽标注掩码） |
| 10% 标签不劣于全标签 | final-state 成功率，1600 回合配对，非劣界 3 个点 | 中 |
| 通用性 | ALFWorld / WebShop | 高 |

成功率比较不再是唯一支柱，这是中稿概率能上升的主要原因。

### 1.7 风险

- **9B 模型报出的概率很粗**（只会说 0.9、0.1 之类）。可以让它从离散档位里选，RL 之后再看；Brier 对离散报告同样是恰当的。
- **"RLCR + PPI"的审稿质疑**。要靠 T3 的方差恒等式、T1 在 agent 控制证据下的防操纵性，以及多轮验证行为来区分；写作时把这三点放在最前面。
- **一个必须坦白的局限**：如果无 oracle 后自报一开始就已经很准，那么"失准"这一现象会变弱。但 hacking、标签效率和校准保持这三条主张仍然成立，所以这个风险比 v1 的 K1 小。

## 2. 备选 B：Skill vs. Luck，区分 planner 的本事和执行器的运气（因果 / 鞅控制变量）

- **观察**：在 harness 里，执行器（冻结的 VLA）的随机性对 planner 来说是外生噪声。一次 VLA 调用成不成功，一部分由 planner 的选择决定，一部分是运气。
- **方法**：
  - 从日志学一个执行器能力模型 g(s, a) ≈ P(技能成功 | 状态, 调用)，用交叉拟合；
  - 每次调用的"运气残差"定义为 u_k = o_k − g(s_k, a_k)，其中 o_k 是 harness 内部可见的技能结果（如 pick 的抬升/夹爪判据），不需要任务真标签；
  - 由于 E[u_k | 调用之前的历史] = 0，c · Σ_k u_k 对任何 c（或只依赖历史的 c）都是合法的零均值控制变量，可以从回报里减掉而不引入偏差。这是鞅差分论证，与 exogenous MDP（Dietterich et al., ICML 2018）和 counterfactual credit assignment（Mesnard et al., ICML 2021）一脉相承，但这里外生性由系统结构保证，不需要学习。
- **可选**：在 π0.5 server 里按 (组, 调用序号) 给噪声设种子，实现共同随机数耦合。但 2609.24144 已经研究过这一点，只能作为对照。
- **定位**：创新性中等，大部分实验可以离线完成。最适合作为 A 的一个附加方差缩减模块（"标签噪声 + 执行器运气"两个来源一起处理），或者单独投 CoRL。是否值得做，由 E1 中"执行器运气能解释多少回报方差"这个数决定。

## 3. 快速产出 C：agentic 机器人基准中特权信号捷径的因果审计

- **已发现的泄漏**：
  - RPent 的 `terminated` 字段和 prompt 目标；
  - 成功后调用动作会触发断言报错，VLA 循环会提前退出；
  - CaP-X 配置使用的是真值物体状态（"privileged" API，见 `harnesses/capx_libero/harness.yaml` 头注释）；
  - [Demonstration-Free Robotic Control via LLM Agents (2601.20334)](https://arxiv.org/abs/2601.20334) 也把仿真器成功信号回灌进上下文，作者自己报告了 agent 读取仿真器内部状态的捷径案例。
- **做法**：
  - 对每个特权通道分别做干预（屏蔽或扰动），测 SFT 与 RL 两个开源 planner 对它的"因果依赖度"（干预前后成功率和行为的差异）；
  - 检验 **RL 是否放大了对特权信号的依赖**；
  - 给出无泄漏的评测协议。
- **成本**：只需评测、不需要训练，约 2–3 周 GPU。数据同时充当 A 的 E0 试点。
- **投向与胜算**：NeurIPS 2027 Datasets & Benchmarks 或 CoRL 2027。结果风险低（泄漏已经确证，剩下的只是测出多大），中稿约 25–35%。

## 4. 组合策略与概率（主观估计）

| 方案 | 做出强结果的概率 | 结果成立时的中稿概率 | 单次投稿中稿 | 一年内（含一次重投） |
|---|---|---|---|---|
| v1 方向一（原方案） | ~23% | ~40% | ~10% | ~18% |
| **A：Self-Grading** | ~35–40% | ~45% | ~15–18% | ~28% |
| B：Skill vs. Luck（单独投） | ~30% | ~35% | ~10% | ~18% |
| **C：泄漏审计** | ~80% | ~30–35% | ~25% | ~35% |
| **C 先行 + A 主线** | | | | **至少一篇 A 类中稿约 45–50%** |

说明：
- 主会单篇的接收率本身约 25%，执行很好的论文大约 40–50%。所以任何单个方向的单次中稿概率都很难超过 30%。真正能拉高的是三件事：
  - 减少结果风险（早做否决检查）；
  - 让主张落在高功效指标上；
  - 用组合降低整体风险。
- A 比 v1 高，主要是因为两条高功效主张（hacking 与校准）基本不依赖在线成功率能否拉开差距，再加上 T1–T4 本身没有经验风险。

## 5. RTX PRO 5000 72GB 对可行性的影响

已知规格（零售商页面，非 NVIDIA 官方规格表）：
- 72GB GDDR7，384-bit，带宽约 1344 GB/s；
- FP32 约 65 TFLOPS；
- PCIe 5.0，**无 NVLink**，300W。
- 来源：[Scan](https://www.scan.co.uk/products/72gb-pny-nvidia-rtx-pro-5000-blackwell-14080-cuda-400-tensor-100-rt-gddr7-ecc-pcie-50x16-4x-dp-retai)、[Guru3D](https://www.guru3d.com/story/nvidia-introduces-3-gb-gddr7-modules-in-professional-gpu-rtx-pro-5000-blackwell-with-72-gb/)、[PNY](https://www.pny.com/nvidia-rtx-pro-5000-72gb-blackwell)。
- BF16 tensor 算力没有查到官方数字，按 Blackwell 工作站卡的常见比例粗估稠密 BF16 约 250 TFLOPS，需要以官方规格表或实测为准。

影响：

1. **rollout 会比预注册里假设的慢。** vLLM 的解码受显存带宽限制：9B bf16 权重约 18 GB，每秒最多约 75 个解码步，大约是 H100 的 40%。单回合耗时很可能是 15–25 分钟，而不是预注册里假设的 10 分钟，rollout 和评测时间要乘 1.5–2.5。
   - 加速选项：rollout 用 FP8 权重服务，带宽减半，解码约快 1.7 倍。由于 proxy 记录的就是采样端自己的 logprob，截断 IS 会修正训练端与采样端的差异。但要在 E0 用 gate-B 统计确认偏差可接受；评测仍用 bf16，保证可比。
2. **训练受影响不大。** 44k token 的样本计算密度很高，FSDP 在 PCIe 上的通信可以被计算掩盖，没有 NVLink 问题不大。按有效 100–120 TFLOPS 估算，每个样本约 30–40 秒，与预注册假设一致。
3. **方案 A 的算力**（单回合按 20 分钟）：
   - 9 个 run 约 14 天；
   - 最终评测约 8 天；
   - C（兼作 E0）约 3 天；E1 约 1.5 天；ALFWorld 约 4 天；
   - 合计约 31 天，加 40% 余量约 6 周。arm 数减少，抵消了 rollout 变慢。
